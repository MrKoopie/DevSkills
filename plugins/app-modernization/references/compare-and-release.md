# Compare and determine readiness

Compare immutable baseline and candidate snapshots by stable IDs. Verify their source,
repository, product/test revisions, running app and fixture identity before executing
checks. Drift invalidates affected evidence; refresh it before reporting a verdict.
Use baseline adapters when needed; do not overwrite the original evidence with candidate
output. Separate execution/setup failures from changed product behavior.

For each required coverage row, record the preserved contract or agreed improvement,
before/after test and visual evidence, result and remaining action. Results:

| Result | Required basis |
| --- | --- |
| equivalent | Shared meaningful input produces the required observable behavior |
| improved | Demonstrated benefit meets a stated improvement/correction criterion |
| intentional change | Explicitly agreed contract change meets its acceptance criteria |
| regressed | Candidate violates a preserved or agreed contract |
| unverified | Required execution, identity or evidence is missing |

Compare paired screenshots using comparable fixtures/viewports, plus semantic assertions
for permissions, calculations, persistence, documents and effects. Document field/layout
requirements need output verification independent of UI screenshots. Check replacement
dependency contracts, worker/runtime behavior and real data-upgrade paths where affected.
Do not infer improvement from changed pixels, code cleanliness or aggregate test counts.

## Independent final audit

Discover `feedback-triage:validate-original-request` from the installed skill catalog and
read its actual contract; do not hardcode sibling plugin/cache paths. It owns source
resolution, three-role sequencing, snapshot identity, negative testing, report reconciliation
and final screenshot inspection. Invoke it unchanged at final validation (or an expressly
requested intermediate audit). It requires a complete work item or explicitly confirmed
conversation fallback; reuse an already confirmed source, never silently manufacture one.

Give reviewers its permitted source/snapshot/run handoff, not the orchestrator's feature
list or expected verdict. They discover requirements independently. The modernization
inventory remains evidence they can examine, not an authoritative scope substitute.
Inspect every screenshot embedded in the final audit report as its contract requires;
selective loading during ordinary work does not waive final inspection.

If the companion skill or required native delegation is unavailable, disclose the missing
audit and withhold a complete independent verdict. Continue unaffected permitted work.
For cross-repository rewrites, compare the two named snapshots here; run the unchanged
validator against the candidate's resolvable base/head and agreed source. Do not pass a
foreign-repository SHA as its base. Historical equivalence proof remains in the comparison.

## Completion

Run all required candidate checks at the recorded revision; reconcile mapped/excluded/
unmapped inventory and all required scenarios, improvements and technical contracts.
Preserved behavior must pass, agreed improvements must meet criteria, and relevant
migration/operational proof must exist. Required unverified results or unexplained
regressions prevent a complete verdict, even if other checks pass. Explicit user scope
reductions/waivers are reported as limitations, not full coverage of the original request.
Report readiness separately from authorization to merge, deploy or cut over. Give the
index/comparison/report paths, proven results and remaining actions concisely.
