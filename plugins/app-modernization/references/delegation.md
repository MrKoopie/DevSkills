# Delegation and companion skills

Delegate independent discovery when it reduces context or separates ownership. Parent
owns shared registers and waits for returns before reconciliation. Use disjoint surfaces
or paths; do not assign concurrent edits to the same application files. Give agents the
source, snapshot identity, scope, run/browser capabilities, allowed effects, owned output
paths and the absolute [discovery contract](discovery-contract.md) path. Do not copy the
whole conversation or load every specialist skill. Avoid nested delegation.

| Harness | Discovery dispatch |
| --- | --- |
| Codex | Use the exposed native subagent tool with fresh context and the contract path. Read its actual schema; no globally installed custom role is assumed. |
| Claude Code | Use the discovered `app-modernization:baseline-discovery` agent, or a fresh native agent with the same contract path. Resolve plugin paths through the loaded catalog. |

The Claude descriptor only routes to the shared contract. This plugin supplies no model
override, hook or external reviewer. Follow the user's requested models when available;
do not silently substitute unavailable ones. Discover browser access separately for each
agent; a parent browser does not imply child access. Missing optional discovery delegation
allows the parent to capture the baseline directly, with no independent-review claim.

Load companion framework skills only for their actual phase. Laravel uses `laravel`'s
architecture/implement/testing skills. Other frameworks use available equivalents and
their current primary documentation. The independent final audit specifically needs the
available `feedback-triage` validator and its own agents/contract; never replace missing
required roles with this discovery agent. Companion plugins are resolved at runtime and
are not installed automatically.

Packaging describes discovery paths, not verified client/runtime capability. Record actual
successful delegation, browser use and returned evidence separately when testing a host.
